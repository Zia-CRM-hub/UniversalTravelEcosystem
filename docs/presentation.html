Project overview

Universal Travel
Ecosystem

One open-source backend. Four front doors. Plan and book travel from the web, a mobile app, an AI concierge and WhatsApp — as a multi-tenant SaaS.

The idea

One platform for every kind of trip

🌐

Meet travellers anywhere

Web, mobile, chat and WhatsApp all call the same API — no business rules live in the clients.

🧩

Pluggable inventory

Flights, trains, buses and hotels sit behind a single supplier interface. New inventory means implementing one class.

🏢

Built as SaaS

Platform → tenant → organization → user, with isolation, travel policy, audit and instant suspension.

Core design

Checkout saga: never charged for a failed trip

1 · CreateValidate offers, sum price, open gateway order
›
2 · HoldCustomer pays; money is held, not taken
›
3 · BookWrite pending, call supplier, mark confirmed — per offer
›
4 · CaptureOnly after every supplier confirmed

If any booking fails

  • Cancel supplier orders already placed
  • Void the payment hold
  • Checkout → failed

Guarantees

  • Idempotent confirm — retries never double-book
  • No endpoint books without a checkout
  • Booking row exists before the supplier call
AI concierge

An agent that can’t invent a price

Read-only by design

  • Tools: search_transport, search_hotels, plan_trip
  • Cannot book or take payment
  • Hands off a Book link to the web app

Safety choices

  • Prices and links rendered by code, not typed by the model
  • Supplier text treated as data (prompt-injection aware)
  • History stores visible dialogue only

WhatsApp adds HMAC webhook verification, instant 200 with background reply, message de-duplication and a 10/min per-sender cap.

Multi-tenant SaaS

Platform → Tenant → Organization → User

RoleScope
Super adminWhole platform; onboard tenants
Tenant adminOne customer tenant
Org adminOne organization
MemberOwn bookings only

Built-in controls

  • Every query filtered by tenant
  • Tenant and user re-checked on every request
  • Per-tenant supplier allow-list, branding, plan limits
  • Org travel policy (spend limit per trip)
  • Append-only audit of admin actions
  • Out-of-scope ids return 404, not 403
Reliability & security

Designed for failure

Resilience

  • Concurrent supplier fan-out with per-call timeouts
  • Failures become warnings, not errors
  • Circuit breaker (5 failures, 30s retry)
  • Retries on GETs only; orders never auto-retried
  • CRITICAL logs for capture failures and stuck bookings

Security

  • scrypt passwords, signed JWT sessions
  • Clients send only offer_id — no price tampering
  • Payment signature, order, amount and status verified server-side
  • Supplier payloads and secrets never reach clients
  • Refuses to start in production with weak or demo config

Try it

python -m venv .venv && .venv/Scripts/activate
pip install -r requirements-dev.txt
python ../scripts/demo.py
